# 架构与上游边界

功能完成度见[功能状态与限制](status.md)。

工作区分为 `core`、`ui` 与 `app`：`core` 处理磁盘状态、下载、进程、npm 元数据、插件兼容和日志脱敏；`ui` 只定义 Slint 页面与事件；`app` 将事件接到异步服务。核心逻辑不依赖 Slint，以便在无图形环境测试。

界面由三层组成：`ui/theme.slint` 提供设计令牌（颜色、字号、圆角、间距、动效）；`ui/components/` 提供可复用组件（`common`、`navigation`、`lines`、`lists`、`dialog`、`tabs`）；`ui/pages/` 提供页面（首页、安装、实例列表、插件市场、实例详情、设置、日志）。`ui/app.slint` 只负责无边框窗口外壳、页面路由与状态，通过属性与回调连接 `app`。`ui/icons.slint` 与 `ui/assets/` 下的占位图由脚本生成，详见 [界面设计](ui-parity.md)、[页面规范](ui-pages.md) 与 [UI 图形资源清单](ui-assets.md)。

启动器只管理 Harness，不修改 Harness 源码。安装版本以 npm `@deepseek-ai/dsh@<精确版本>` 为准。启动时使用该安装的 `bin` 入口、实例工作目录及实例专属 `DSH_HOME`。插件操作使用同一版本的 `dsh plugin --profile web`，不得使用系统全局的 `dsh`。

网络来源限定为 Node.js 官方发行索引、npm registry、插件目录和 GitHub 元数据。安装前验证 Node 官方 SHA256 与 npm 包的 integrity。Node 下载使用临时目录；Harness 直接安装在最终实例目录，因为 Windows 上 pnpm 链接不能随目录移动。成功验证后才写入 `instance.json`，因此失败安装不会出现在实例列表。

界面参考 HMCL 的导航结构，图标、壁纸和角色图由本项目独立创作。

验收：两个版本同时运行时，入口、工作目录、端口和 `DSH_HOME` 均不串用；停止一个实例不会终止另一个实例。

## 离线使用已安装运行时

启动已有实例时，先从本地 `runtimes/node/24.*` 中选择最新且可执行的 Node.js 24 LTS；只有本地不存在有效运行时才查询官方索引并下载。这样网络中断时，已安装实例仍可启动与管理插件。安装新实例仍通过 npm 获取 Harness 精确包版本。验收：官方索引不可达但本地运行时可用时，`ensure_node24` 不发起网络请求。

真实版本的测试记录见[验证记录](verification.md)；当前上游异常见用户手册中的上游版本公告。

## 上游版本目录、预览版与公告

安装页从 npm 官方 `@deepseek-ai/dsh` 目录读取版本，按语义版本排序，列出可点击的精确版本，包括 `alpha`、`beta`、`rc` 等预览版。选中时填写精确版本，仍由 npm 精确包元数据核验安装。页面应明确标出预览版，不能把 npm 的 `latest` 标签与语义版本最高的预览版混称。版本目录的单次核验结果见[验证记录](verification.md)。

首页和安装页提供带原始来源与核验日期的上游版本公告。未获维护者确认的故障报告不得表述为安全公告或已修复的问题。

启动器不修改上游 Harness 的依赖声明、profile patch 或 HMR 启动逻辑。保持主包精确版本安装及独立实例隔离；上游依赖按其发布包声明解析。安装目录不得写入针对 `@deepseek-ai/*` 包的 pnpm `overrides`；`allowBuilds` 仅在用户逐项批准构建脚本后写入。若特定上游版本安装或启动失败，保留可诊断错误并在公告与用户手册中解释。

验收：安装页能选择 `0.1.7-alpha.2` 等真实预览版本；版本列表展示 npm 目录返回的全部已发布版本并支持滚动，不设固定条数上限；默认填写 npm 版本目录中语义版本最高的精确版本，且明确标记预览版；公告准确链接原报告；实例安装不产生上游依赖覆盖，`0.1.5-rc.2` 不注入修复参数或改写 profile。

## 模型路由与凭据

启动器不再提供 API Key、端点或默认模型的编辑界面；这些设置由每个实例的 DeepSeek Harness 本体管理。设置页只包含启动器相关的界面项，未接入的操作见[功能状态与限制](status.md)。第三方认证与未知配置格式同样在 Harness 原生界面或插件中处理。

启动器不写入或改写实例的 `.credentials.yaml` 与 `settings.yaml`；这些文件由实例的 Harness 本体维护。启动器只在展示运行日志前读取其中已知密钥用于脱敏，并对 `sk-...` 与 `token=` 形式做正则脱敏，避免密钥进入日志与错误信息。

验收：启动器界面不提供写入 Harness 凭据或模型设置的入口；设置页不含 Harness 凭据编辑项；日志与错误中不出现已知密钥；实例的未知配置不因启动器而改变。
