# 文档先行与 Git 工作流

状态：已实施（仓库建立后生效）。

每项用户可见功能按三个可构建提交进入历史：

1. `docs(dev): ...`：先写行为、上游契约、失败路径和验收条件，标记“计划中”；
2. `feat:` 或 `fix:`：实现代码和测试，把对应开发者文档标为“已实现”；
3. `docs(user): ...`：补操作步骤、截图说明和排障。

一次提交只覆盖一个可回滚的功能切片。提交前运行适用的格式、测试或文档构建检查；不得提交密钥、实例数据、下载的运行时和生成的书籍。发行版本使用 Git 标签；保留分阶段提交，不将整项功能压成单个提交。

内部重构没有用户行为变化时，可以省去用户文档提交，但必须更新受影响的开发者文档。PR 说明列出设计文档、测试结果和用户文档位置。
